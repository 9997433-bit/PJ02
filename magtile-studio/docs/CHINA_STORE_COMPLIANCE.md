## 2. 软件著作权登记 (软著)

**为什么是 P0**: 全部国内安卓商店提交应用时必查软著证书 (电子版或
彩色扫描件), 无证书无法通过资质初审 ([STORE_LISTING.md](STORE_LISTING.md)
§4.1 资质前置表第一行; [COMMERCIAL_PLAN.md](COMMERCIAL_PLAN.md) §6.3
明确为国内上架前置项)。办理机构为中国版权保护中心 (CPCC), 普通流程
受理后约 30~40 个工作日发证, 可付费加急 —— **是全清单里周期最长的
串行项, 必须最先启动**。

### 2.1 办理清单

- [ ] **P0 · 行政** — 确定登记主体: 以公司营业执照为申请人 (个人登记
      无法用于企业开发者账号上架); 运营主体全称与
      [PRIVACY_POLICY_DRAFT.md](PRIVACY_POLICY_DRAFT.md) §1「我们是谁」
      的法务定稿项同一主体, 一处定稿两处同步。
- [ ] **P0 · 行政 + 法务顾问** — 确定登记名称与版本号: 建议
      「MagTile Studio 磁力片工坊软件 V1.0」。**软著名称必须能与商店
      应用名对应** (应用名见 [STORE_LISTING.md](STORE_LISTING.md) §2:
      「MagTile Studio 磁力片工坊」), 名称对不上是国内商店最常见驳回
      原因之一; 若商店字段用短名「磁力片工坊」, 登记名称须包含该短名。
- [ ] **P0 · 工程** — 准备源程序材料: 连续源代码前 30 页 + 后 30 页
      (每页 ≥50 行, 末页为程序结尾), 页眉标注软件名称与版本号;
      从 `core/` 等自研目录截取, **不含第三方库代码** (nlohmann/json、
      GLFW 等第三方组件不属登记范围, 许可清单见
      [COMMERCIAL_PLAN.md](COMMERCIAL_PLAN.md) §6.2)。
- [ ] **P0 · 产品/运营 + 工程** — 准备文档材料: 操作手册/用户手册
      前 30 页 + 后 30 页 (不足 60 页全交), 含界面截图与功能说明;
      截图口径与 [STORE_LISTING.md](STORE_LISTING.md) §5 真实界面红线
      一致 —— 不得使用合成界面。
- [ ] **P0 · 行政** — 在中国版权保护中心在线提交申请表 + 营业执照
      副本扫描件 + 上述材料, 跟踪受理与补正通知; 评估是否加急
      (以商店提交目标节点倒排, 普通件周期覆盖不了就加急)。
- [ ] **P1 · 行政** — 取证后: 电子证书 + 彩色扫描件归档到公司资质库,
      分发给各商店后台上传 (OPPO / vivo 查原件扫描,
      [STORE_LISTING.md](STORE_LISTING.md) §4.2); 证书关键信息
      (登记号/名称/版本) 登记进第 9 节总控清单。
- [ ] **P1 · 行政** — 大版本更名或产品名变更时评估补充登记新版本;
      软著版本与商店版本无需一一对应, 但名称对应关系不能断。

## 3. App 备案 (工信部 ICP 备案)

**为什么是 P0**: 依据工信部 2023 年 8 月《关于开展移动互联网应用程序
备案工作的通知》, 未履行备案手续的 App 不得提供互联网信息服务 ——
各商店自 2023 年 9 月起强制校验备案号, 未备案不得上架、存量未备案
应用下架 ([STORE_LISTING.md](STORE_LISTING.md) §4.1)。备案主体、App
名称、包名、签名公钥/MD5 绑定, **包名 `com.magtile.studio` 上架后
不可改, 备案信息同样围绕它锁定**。

### 3.1 办理清单

- [ ] **P0 · 行政** — 前置: 企业主体就绪 (营业执照、法人实名、
      对公账户); 与软著登记主体、隐私政策署名主体三者同一。
- [ ] **P0 · 行政 + 产品/运营** — 选择备案通道: 经网络接入服务商
      (阿里云/腾讯云等, 若隐私政策官网托管在其云上可同通道办理) 或
      经应用分发平台发起 App 备案, 报主体住所地省通信管理局审核。
- [ ] **P0 · 工程** — 导出备案要件: 正式 release 签名的包名、签名
      证书公钥与 MD5 (当前 Gradle 仅出 debug APK, release 签名就位是
      前置工程项, 见 [STORE_LISTING.md](STORE_LISTING.md) §1);
      **备案用签名与商店提审包签名必须一致**, 换签名要变更备案。
- [ ] **P0 · 产品/运营** — 如实申报服务内容: 教育/工具类, 面向
      未成年人使用的 App 在备案表单中按实勾选 (备案系统对未成年人
      相关服务有单独标记位)。当前版本零网络代码
      ([PRIVACY_POLICY_DRAFT.md](PRIVACY_POLICY_DRAFT.md) §5),
      申报口径: 不含自建服务端域名; 若隐私政策官网域名启用 (第 5 节),
      该域名的网站 ICP 备案先行或同步办理。
- [ ] **P0 · 工程** — 取号后应用内展示: 备案号 (格式
      「X ICP 备 XXXXXXXX 号-XA」) 展示在应用内显著位置 —— 落点
      「家长中心 / 设置 → 关于」页, 与隐私政策入口同屏; 该展示为
      备案通知的明示要求, 商店审核会抽查。
- [ ] **P1 · 产品/运营** — 各商店后台回填备案号并通过其与工信部
      系统的联查校验 (应用宝/小米等已接入自动核验); 备案号与
      应用名/包名/签名不一致会卡审。
- [ ] **P1 · 行政** — 官网 (若上线) 完成网站公安备案 (全国互联网
      安全管理服务平台) 并在页脚展示; 部分商店资质复审会看官网
      合规性。
- [ ] **P1 · 行政** — 建立变更台账: App 名称、包名、签名、主体任一
      变更须先变更备案再发版, 写入发版检查流程。

## 4. 儿童应用年龄分级与未成年人保护申报

**口径**: 本应用为**教育工具类, 非网络游戏** —— 不触发游戏版号与
防沉迷实名体系; 若商店表单误按「游戏」分类, 以「教育工具类应用」
申诉 ([STORE_LISTING.md](STORE_LISTING.md) §7.2 既定口径, 本文不重复
定义只列办理动作)。《未成年人网络保护条例》对照结论复用
[SECURITY_AND_PRIVACY.md](SECURITY_AND_PRIVACY.md) §4.2 (Z1~Z9) 与
[PRIVACY_POLICY_DRAFT.md](PRIVACY_POLICY_DRAFT.md) §8。

### 4.1 办理清单

- [ ] **P0 · 产品/运营** — 逐家商店完成适龄/未成年人保护表单申报,
      统一口径: 教育类 / 无社交 / 无陌生人交互 / 无 UGC / 含家长
      控制 (家长门) / 含应用内购买 (家长门后); 预期各商店最低适龄档
      (全年龄 / 3+ / 8+, 随商店体系,【以后台为准】), 答案与
      [STORE_LISTING.md](STORE_LISTING.md) §7.2 逐字对齐。
- [ ] **P0 · 法务顾问** — 《儿童个人信息保护声明》独立成文并定稿
      (SECURITY_AND_PRIVACY §4.2 Z2, PRIVACY_POLICY_DRAFT §8 的法务
      定稿项): 通俗表述、独立于通用隐私政策、含监护人权利与联系
      通道; 国内商店儿童向应用资质项之一
      ([STORE_LISTING.md](STORE_LISTING.md) §4.1)。
- [ ] **P0 · 法务顾问 + 行政** — 指定儿童个人信息保护专员并写入
      公司制度与《儿童个人信息保护声明》(SECURITY_AND_PRIVACY §4.2
      Z3 的商用发布前置; 专员姓名/职务不必公开, 联系通道必须公开)。
- [ ] **P1 · 产品/运营** — 若单店设「儿童/亲子」专区 (如华为儿童
      专区), 评估入驻要求后再申报 —— 专区曝光高但审核项更多, V1
      以通过教育类目标准审核为先, 专区入驻可后置。
- [ ] **P1 · 产品/运营 + 法务顾问** — 保留「非学科培训」自证材料:
      产品为磁力片搭建教程工具, 不属 K12 学科培训, 不适用办学许可/
      学科类校外培训资质; 预写申诉话术备用 (教育类目误判为学科培训
      是国内商店常见卡点)。
- [ ] **P1 · 工程** — 家长门强度复核: 随机算术题 + 错误冷却已落地
      (SECURITY_AND_PRIVACY §2.2), 提审前按各商店未成年人保护审核项
      实测一遍儿童侧不可达路径 (付费/外链/设置全部门后)。

## 6. 订阅与自动续费披露

**口径**: 价格与商品结构以 [COMMERCIAL_PLAN.md](COMMERCIAL_PLAN.md)
§2~§3 为唯一事实来源; 商店详情页披露文案以
[STORE_LISTING.md](STORE_LISTING.md) §9.2 为唯一版本; 儿童侧零价格
红线见 STORE_LISTING §9.3。本节只列合规动作与法规对表。

### 6.1 办理清单

- [ ] **P0 · 法务顾问** — 自动续费合规对表:《消费者权益保护法实施
      条例》(2024-07-01 施行) 对自动展期/自动续费要求「以显著方式
      提请消费者注意 + 扣费前显著提醒」—— 核对: ① 商店详情页披露
      文案 ([STORE_LISTING.md](STORE_LISTING.md) §9.2 已含自动续订
      与取消路径条款); ② 应用内订阅页在购买按钮同屏明示周期、价格、
      自动续订与取消方式; ③ 续费前提醒由商店计费体系承担 (支付
      主体是商店, [STORE_LISTING.md](STORE_LISTING.md) §9.3), 留存
      各商店续费提醒机制说明作合规佐证。
- [ ] **P0 · 产品/运营** — 商店后台商品配置与详情页披露逐字对齐:
      商品表 (STORE_LISTING §9.1) 的定价、周期、家庭档设备数与
      披露文案完全一致, 明码标价, 无「部分功能收费」类模糊表述
      (国内商店对含付费应用的明示要求, STORE_LISTING §4.2)。
- [ ] **P0 · 产品/运营 + 工程** — 红线自查: 无免费试用自动扣费、
      无抽卡/盲盒随机付费、儿童侧零价格零促销
      ([COMMERCIAL_PLAN.md](COMMERCIAL_PLAN.md) §2.5 §3.2 明确不做;
      工程侧以 [STORE_LISTING.md](STORE_LISTING.md) §9.3 审核自查
      双用清单过一遍实机)。
- [ ] **P1 · 法务顾问** — 7 天无理由退款承诺的履约路径落文档: 年度
      订阅退款走各商店退款通道, 客服口径与商店规则冲突时以更有利
      于消费者者为准 (COMMERCIAL_PLAN §3.2 承诺不能只写在详情页)。
- [ ] **P1 · 产品/运营** — 广告法极限词终查: 详情页/截图/推广位
      无「最」「第一」「保证学会」类表述 (STORE_LISTING §10 红线,
      提交前三查之一)。

## 7. 数据安全自评估要点

**结构性优势**: 当前版本零网络代码、零账号、零第三方 SDK、零数据
收集 ([SECURITY_AND_PRIVACY.md](SECURITY_AND_PRIVACY.md) §3 数据
清单; [PRIVACY_POLICY_DRAFT.md](PRIVACY_POLICY_DRAFT.md) §2~§5) ——
自评估结论简单, 但**必须成文留档**: 商店隐私检测与监管抽查看的是
「有没有做过评估」的证据, 不是口头结论。

### 7.1 办理清单

- [ ] **P0 · 法务顾问 + 工程** — 出具《个人信息保护影响评估 (PIA)
      备忘录》: 依 PIPL 第 55/56 条, 面向不满 14 周岁儿童 = 敏感
      个人信息场景, 结论「当前版本不处理任何个人信息, 不触发处理
      活动」+ 依据 (SECURITY_AND_PRIVACY §3.1 全量数据清单、§3.2
      永不采集红线) + 触发重评的条件 (新增任何网络功能/账号/SDK),
      签署归档。
- [ ] **P0 · 工程** — manifest 权限自查并出报告: 目标**零敏感权限**
      ([STORE_LISTING.md](STORE_LISTING.md) §4.1 权限清单说明行);
      逐权限用途说明表随提审提交, 商店隐私填报「收集类型」全部勾
      「不收集」、权限逐项「未申请」(STORE_LISTING §8.2 同口径)。
- [ ] **P0 · 工程** — 第三方 SDK 清单申报: **空清单** (零第三方
      分析/广告/推送 SDK, SECURITY_AND_PRIVACY §2.2「越权数据上报」
      缓解措施); 各商店 SDK 填报表如实填「无」—— 小米/华为的自动化
      隐私扫描对「未同意隐私政策前 SDK 初始化采集」查得最严, 零 SDK
      架构天然通过, 但填报不实会被扫描结果打脸。
- [ ] **P1 · 工程** — 发布前网络流量审计: 抓包验证提审包零外联
      (SECURITY_AND_PRIVACY §11 规划的审计流程), 报告归档 —— 这是
      「完全离线」宣传口径 (STORE_LISTING §2.2) 的工程证据。
- [ ] **P1 · 法务顾问** — 不适用项留痕: 数据出境安全评估 (无数据
      出境)、算法备案 (推荐仅本地规则排序, 无画像无服务端算法,
      SECURITY_AND_PRIVACY §4.2 Z9)、等级保护定级 (无自建信息系统)
      —— 逐项写明「不适用 + 理由 + 触发条件」, 与 PIA 备忘录同册。
- [ ] **P1 · 产品/运营** — 数据安全事件响应联络表: 泄露事件告知
      监护人与主管部门的流程 (SECURITY_AND_PRIVACY §4.2 Z7、
      PRIVACY_POLICY_DRAFT §8) 落到具体责任人与时限, 商用发布前
      演练一次。

## 8. 各安卓商店特殊要求

**通用资质前置** (任一商店缺一不可) 见
[STORE_LISTING.md](STORE_LISTING.md) §4.1, 素材差异见其 §4.2; 本节
只列**逐家的行政/资质动作**, 全部标注【以后台为准】—— 商店规则随
政策变动, 提交当周以后台实际表单复核。

### 8.1 华为 AppGallery (优先级最高)

- [ ] **P0 · 行政** — 企业开发者实名认证: 营业执照 + 法人认证/对公
      打款验证; 账号主体与软著、备案主体一致。
- [ ] **P0 · 产品/运营** — 资质上传: 软著电子证书、App 备案号
      (华为后台联查校验)、隐私政策 URL + 《儿童个人信息保护声明》
      URL; 图标另出 216×216 PNG、平板截图单独提交
      ([STORE_LISTING.md](STORE_LISTING.md) §4.2 §6 —— 华为平板是
      国内家庭平板主力, 实机截图必做)。
- [ ] **P1 · 工程** — 预过华为自动化隐私检测: 华为对隐私政策弹窗
      时序与实际行为一致性做机器扫描; 本应用零收集零 SDK, 重点是
      首启不弹多余授权、隐私入口可达 (家长中心/设置摘要已落地,
      SECURITY_AND_PRIVACY §4.1 C2)。
- [ ] **P1 · 产品/运营** — 教育类目资质问询预案: 备好「非学科培训」
      自证材料 (第 4 节 P1 项), 华为教育类目复审最细。

### 8.2 小米应用商店

- [ ] **P0 · 行政** — 小米开放平台企业开发者认证 (营业执照 + 打款
      验证); 软著 + 备案号上传, 备案信息与工信部系统联查。
- [ ] **P0 · 产品/运营** — 简介按小米字数限制从
      [STORE_LISTING.md](STORE_LISTING.md) §2.1 裁剪 (不另写新口径,
      STORE_LISTING §4.2); 隐私政策 URL 填报。
- [ ] **P1 · 工程** — 预过小米隐私合规检测 (自动扫描 + 人工复测):
      重点核对隐私填报的「不收集」与包内实际行为一致 —— 零网络包
      天然通过, 但填报表必须与第 7 节权限/SDK 报告同口径。

### 8.3 OPPO 软件商店

- [ ] **P0 · 行政** — OPPO 开放平台企业认证; **软著原件彩色扫描件**
      上传 (OPPO 查原件扫描, [STORE_LISTING.md](STORE_LISTING.md)
      §4.2), ICP 备案号核验。
- [ ] **P1 · 产品/运营** — 表单与 vivo 接近 (STORE_LISTING §4.2),

### 8.4 vivo 应用商店

- [ ] **P0 · 行政** — vivo 开放平台企业认证; 软著扫描件 + ICP 备案

      §4.2)。
- [ ] **P1 · 产品/运营** — 首提人工审核较严: 预留一轮驳回-申诉的

### 8.5 应用宝 (腾讯, 优先级第二)

## 9. 总控清单 (P0 汇总 + 串行关键路径)

### 9.1 P0 汇总表 (全部完成才进入任一商店提交流程)

| # | 事项 | 节 | 主责 | 串行依赖 |
| --- | --- | --- | --- | --- |
| 1 | 软著登记 (主体/名称/材料/申请) | §2 | 行政 | 无 —— **最先启动 (周期最长)** |
| 2 | App 备案取号 + 应用内展示备案号 | §3 | 行政 + 工程 | release 签名就位 |
| 3 | 官网域名 + 网站 ICP 备案 + 隐私政策/儿童声明 URL 上线 | §5 | 行政 + 法务顾问 | 运营主体定稿 |
| 4 | 隐私政策与《儿童个人信息保护声明》法务定稿 | §4/§5 | 法务顾问 | 运营主体定稿 |
| 5 | 儿童个人信息保护专员任命 | §4 | 法务顾问 + 行政 | 无 |
| 6 | 适龄/未成年人保护表单逐家申报 | §4 | 产品/运营 | 各商店账号就绪 |
| 7 | 自动续费披露对表 + 商品配置对齐 | §6 | 法务顾问 + 产品/运营 | 付费闭环就绪 (COMMERCIAL_PLAN §2.2) |
| 8 | PIA 备忘录 + 权限自查报告 + SDK 空清单申报 | §7 | 法务顾问 + 工程 | 提审包冻结 |
| 9 | 五家商店企业开发者认证 + 资质上传 | §8 | 行政 + 产品/运营 | 1~4 完成 |

### 9.2 关键路径提示

```
运营主体定稿 ──→ 软著申请 (周期最长, 先行) ──→ 证书 ──┐
      │                                               ├─→ 五家商店资质上传 ──→ 提交审核
      ├─→ 域名注册 + 网站 ICP 备案 ──→ 隐私 URL 上线 ──┤
      └─→ release 签名 ──→ App 备案取号 ──→ 应用内展示 ─┘
```

- 风险登记与驳回沟通记录: 各商店审核往返在本表下追加行维护
  (驳回原因 / 申诉口径 / 结果), 不散落在个人聊天记录里。
- 提交前最后一步: 跑 [STORE_LISTING.md](STORE_LISTING.md) §11 提交前
  核对清单 + `python3 tools/check_china_compliance_docs.py` (本文
  章节与条目完整性守卫)。
